*review.txt*  コードレビュー用コメントを外付けで残すローカルプラグイン

==============================================================================
概要                                                                  *review*

レビュー中のコードに、ソースを書き換えずにコメントを付けるための自作モジュール
(`lua/review/init.lua`)。行(範囲)を選んでコメントを書くと、git root 直下の
`.review/` に保存され、エディタ上にはサインと仮想行で表示される。
まとめて Markdown としてヤンクして PR や Slack に貼ることを想定している。

保存先 (git root が無ければ cwd) ~
>
    .review/comments.json   データ本体 (パス・行番号・本文)
    .review/REVIEW.md       貼り付け用 Markdown (保存のたびに再生成)
<
`.review/` を commit したくなければ .gitignore に追加する。
コメントが 0 件になると両ファイルとも削除される。

行番号は extmark で追従するので、コメントより上の行を増減しても `:w` した
時点でデータ側の行番号が更新される。

==============================================================================
キーマップ                                                   *review-mappings*

                                                                  *<leader>aa*
<leader>aa              カーソル行にコメントを付ける。
                        ビジュアルモードなら選択範囲に付ける。

                                                                  *<leader>ae*
<leader>ae              カーソル位置のコメントを編集する。
                        複数あれば |vim.ui.select()| で選ぶ。

                                                                  *<leader>ad*
<leader>ad              カーソル位置のコメントを削除する。

                                                                  *<leader>al*
<leader>al              コメント一覧を Telescope で開く。<CR> でジャンプ、
                        <C-d> で削除。Telescope が無ければ quickfix。

                                                                  *<leader>ay*
<leader>ay              プロジェクトの全コメントを Markdown にして
                        + レジスタ(クリップボード)と無名レジスタに入れる。

                                                                  *<leader>aY*
<leader>aY              現在ファイルのコメントだけをヤンクする。

                                                                  *<leader>ao*
<leader>ao              `.review/REVIEW.md` を開く。

                                                                  *<leader>ap*
<leader>ap              未投稿のコメントを gh で PR に投稿する。
                        |review-publish| を参照。

                                                                  *<leader>aP*
<leader>aP              投稿せずに送る内容を確認する (`:Review publish --dry-run`)。

                                                                  *<leader>at*
<leader>at              コメント表示の ON/OFF。

                                                                  *<leader>ax*
<leader>ax              プロジェクトのコメントを全削除する (確認あり)。

                                                                      *]a* *[a*
]a / [a                 現在ファイル内の次 / 前のコメントへ移動する。

==============================================================================
入力フロート                                                   *review-editor*

<leader>aa / <leader>ae で開くフローティングウィンドウは markdown の
スクラッチバッファ。インサートモードの <CR> は普通の改行なので複数行書ける。

    <CR> (ノーマル)     確定
    <C-s> (n/i)         確定
    :w                  確定
    q (ノーマル)        キャンセル
    :q                  キャンセル

本文が空のまま確定するとキャンセル扱いになる。

==============================================================================
コマンド                                                     *review-commands*

                                                                     *:Review*
:[range]Review [sub]    サブコマンド (省略時は add):
                        add       コメントを付ける。[range] があればその範囲
                        edit      編集
                        delete    削除
                        list      一覧
                        yank      全コメントをヤンク
                        yankfile  現在ファイルのコメントをヤンク
                        open      REVIEW.md を開く
                        publish   PR にドラフトレビューとして投稿
                                  (`--dry-run` で内容確認のみ、
                                  `:Review! publish` で投稿済みも含める)
                        toggle    表示トグル
                        clear     全削除 (確認あり)

==============================================================================
GitHub PR への投稿                                            *review-publish*

<leader>ap / `:Review publish` は、未投稿のコメントをまとめて 1 つの
ドラフト (Pending) レビューとして現在ブランチの PR に投稿する。
PENDING なので GitHub 上では自分にしか見えず、内容を見直してから自分で
Submit する。Submit 時に Comment / Approve / Request changes を選べる。

手順 ~
1. `gh pr view` で現在ブランチの PR を探す (無ければエラー)
2. ローカル HEAD と PR の head が違う、または対象ファイルに未コミットの変更が
   あると、行番号がずれる可能性があるので確認ダイアログを出す
3. `gh pr diff` を読み、diff のハンクに含まれない行のコメントは除外する
   (GitHub は diff 外の行にコメントを付けられない)。除外分は通知に出る
4. 既に未送信のレビューがあれば中断する (1 PR に 1 つしか持てない)
5. `gh api POST /pulls/{n}/reviews` で投稿。URL を + レジスタにコピーする

投稿できたコメントには `posted` (PR 番号・URL・日時) が記録され、表示が
薄くなって `[PR #12 投稿済み]` が付く。次回の publish からは外れるが、
ヤンクや REVIEW.md には引き続き含まれる。

<leader>aP / `:Review publish --dry-run` は投稿せずに送る内容を
スクラッチバッファに出す。diff 外で除外されるコメントは `skipped` に並ぶ。
`:Review! publish` は投稿済みのコメントも含めてもう一度送る。

必要なもの: `gh` (ログイン済み) と、PR の head が push 済みであること。

==============================================================================
出力形式                                                       *review-format*

ヤンク / REVIEW.md はコメントごとに次のブロックになる (ファイル順→行順)。
>
    ### app/models/user.rb:L10-L15

    ```ruby
    (10〜15 行目のコード)
    ```

    コメント本文
<
1 行だけなら `:L10`。コードは開いているバッファがあればバッファの内容、
無ければディスクから読む。言語名は |vim.filetype.match()| で決める。

ハイライト                                                 *review-highlights*

ReviewCommentSign       サイン `▎` (既定: DiagnosticInfo にリンク)
ReviewCommentText       仮想行の本文 (既定: DiagnosticInfo の色 + italic)
ReviewCommentBorder     仮想行の `┃` (既定: Comment にリンク)
ReviewCommentPostedSign 投稿済みコメントのサイン (既定: Comment にリンク)
ReviewCommentPosted     投稿済みコメントの本文 (既定: Comment にリンク)
